# Reliable Workspace Test Execution

## Objective

Make `npm test --workspaces` build the artifacts it needs and run only compiled test files. The dashboard application entry point must not be launched by server test discovery.

## Context

- The validation workflow builds workspaces before running tests, but the reported CLI failure shows `packages/cli/dist` was absent when its test command ran.
- Both workspace test commands currently pass the whole `dist` directory to `node --test`.
- The dashboard entry point starts a long-running server on the default port, while server tests use ephemeral ports and close their servers in teardown.
- Related: [Spec 022 — Cross-Platform Test Runner](spec-022-cross-platform-test-runner.md).

## Requirements

1. Each workspace test command must build the server output it consumes before running tests, even when invoked without the root workflow's separate build step.
2. Server test discovery must pass only compiled `*.test.js` files to Node's test runner; it must not execute application entry points from `dist`.
3. The test discovery helper must use Node built-ins only, work on supported Node versions and Windows paths, and return a non-zero status if discovery or a test fails.
4. Preserve the dashboard UI and acceptance preflight test steps and their order after server tests.

## Behavior / Flow

1. The CLI test command compiles the CLI workspace, discovers compiled test files under `dist`, then runs them.
2. The dashboard server test command compiles the server workspace, discovers compiled test files under `dist`, then runs them.
3. The dashboard workspace runs UI tests and preflight tests only after server tests finish successfully.
4. The shared test discovery helper recursively selects files ending in `.test.js` and invokes `node --test` with those explicit file paths.

## Constraints

- Do not change dashboard runtime behavior, server defaults, existing test assertions, or UI implementation.
- Do not add dependencies or remove the validation workflow's workspace build gate.
- Do not convert missing tests or test failures into successful exits.
- Keep compiled output ignored and generated by the workspace build.

## Edge Cases

| Scenario | Handling |
|----------|----------|
| `dist` is missing before a workspace test command | The command builds the workspace before discovery. |
| No compiled `*.test.js` files are found | The helper reports the missing test files and exits non-zero. |
| `dist` contains `index.js` alongside tests | Only `*.test.js` files are passed to the test runner; the server entry point is not started. |
| A test fails or the child process cannot start | The helper exits non-zero and preserves the failure for CI. |
| Workspace or repository path contains spaces or Windows separators | Paths are passed as process arguments without shell glob expansion. |

## Acceptance Criteria

- AC-01: Given a workspace with no `dist` directory, when its test command runs, then the workspace build runs before test discovery.
- AC-02: Given dashboard `dist` contains both `index.js` and compiled tests, when server tests run, then only compiled `*.test.js` files execute and the default dashboard listener is not started by discovery.
- AC-03: Given no compiled test files exist, when discovery runs, then it exits non-zero with a clear diagnostic.
- AC-04: Given any compiled test fails or the child runner cannot start, when the workspace test command runs, then its exit status is non-zero.
- AC-05: Given server tests pass, when the dashboard workspace test command runs, then UI tests and preflight tests execute afterward in their existing order.

## Done When

- [ ] AC-01 — proven by inspecting workspace test command order and running `npm test --workspaces` from a clean workspace.
- [ ] AC-02 — proven by a focused server-runner check with a runtime entry point present beside a compiled test.
- [ ] AC-03 — proven by a focused empty-discovery check.
- [ ] AC-04 — proven by a focused failing-test and child-runner error check.
- [ ] AC-05 — proven by dashboard workspace test output ordering.
